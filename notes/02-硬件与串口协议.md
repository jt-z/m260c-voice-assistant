# 02 - 硬件与串口协议

## 1. 硬件组成

```
┌─────────────────────────────────────────────┐
│ WHEELTEC M260C 智能音箱                       │
│  ├─ 讯飞 XFM-DP 环形六麦克风阵列               │
│  ├─ M2 系列降噪板（跑唤醒引擎 / 声源定位）        │
│  └─ 板载 USB 声卡（喇叭输出 = C-Media）         │
└───────────────┬─────────────────────────────┘
                │ USB
        ┌───────┴────────┐
        │ CH9102 串口芯片  │  1a86:55d4  → /dev/ttyACM2（控制通道，本项目的核心）
        └───────┬────────┘
                │
   ┌────────────┴──────────────────────────┐
   │ XFM-DP 录音（USB Audio In）             │  16000Hz 单声道 ← 识别用音频
   │ C-Media 播放（USB Audio Out）            │  48000Hz 立体声 ← TTS 播报
   └───────────────────────────────────────┘
```

**要点**：控制通道（串口）和音频通道（USB 声卡）是**两条独立链路**。
唤醒检测和声源定位在降噪板里做完，通过串口上报；PC 只负责录音、识别、决策、播报。

## 2. 串口协议（讯飞 XFM-DP）

来源：客户资料 V6.0 中的离线/在线 SDK 源码（`wheeltec_mic.cpp` / `wheeltec_m2n.cpp` / `service.cpp`）。
实现见 [`mic_serial.py`](../mic_serial.py)，纯标准库 `termios`，**无第三方依赖**。

参数：**115200 8N1，无流控，原始模式**。

### 帧格式

```
偏移   内容                说明
 0     0xA5               帧头 FRAME_HEADER
 1     0x01               用户 ID USER_ID
 2     type               消息类型
 3-4   len  (uint16 LE)   JSON 载荷长度
 5-6   sid  (uint16 LE)   消息序号
 7..   payload             载荷（通常是 JSON，UTF-8）
末尾   checksum            前面所有字节求和取补码： (~sum + 1) & 0xFF
```

```python
# mic_serial.py
def checksum(data):   return (~sum(data) + 1) & 0xFF
def make_frame(t, p, sid=0):
    body = bytes([0xA5, 0x01, t & 0xFF]) + pack("<H", len(p)) + pack("<H", sid) + p
    return body + bytes([checksum(body)])
```

### 消息类型

| type | 名称 | 方向 | 说明 |
|---|---|---|---|
| `0x01` | SHAKE | 设备 → 主机 | 握手请求，载荷固定 `A5 00 00 00`，**必须回 `0xFF` 确认**，否则设备一直重发 |
| `0x04` | AIUI | 设备 → 主机 | 设备事件（唤醒、开机、版本上报等），载荷为 JSON |
| `0x05` | CONTROL | 主机 → 设备 | 上位机下发命令（JSON） |
| `0x06` | VOICE | — | 语音数据 |
| `0xFF` | CONFIRM | 主机 → 设备 | 确认（回握手、回命令） |

### 解析容错

`iter_frames()` 是个生成器，能处理：

- **半包**：长度不够时 `break` 等待更多数据（配合 `_buf` 缓冲）
- **脏字节**：帧头/用户 ID 不匹配时 `i += 1` 逐字节前移重新同步
- **校验错**：丢弃该位置继续找下一个帧头

`read_frames()` 每次读完会把缓冲区**回退到最后一个 `0xA5` 位置**，只保留不完整的尾巴。

## 3. 唤醒事件（0x04）的载荷

不同固件版本的 JSON 结构不一样，代码用**递归提取**兼容（见 `voice_interact_test.py`）：

```python
find_angles(obj)    # 递归找所有 "angle" 数值
find_values(obj, "start_ms")   # 递归找 "start_ms"
has_key(obj, "ivw")            # 递归判断有无 "ivw"
```

三种典型结构都能解析：

```json
{"ivw": {"angle": 130, "beam": 2, "score": 0.9, "start_ms": 123456}}
{"content": {"info": "{\"angle\":130, ...}"}}      ← info 里再套一层 JSON 字符串
{"angle": 130}
```

代码用到的事件字段：

| 字段 | 用途 |
|---|---|
| `angle` | 声源角度（0~359），显示在 HUD 雷达上 |
| `beam` | 波束编号（0~5），HUD 高亮对应方向 |
| `score` | 唤醒置信度 |
| `start_ms` | 唤醒起始时间戳，**用于去重**（固件会重发同一个唤醒） |

**去重逻辑**（`voice_command_demo.py: serial_reader`）：

```python
stamp = tuple(find_values(obj, "start_ms"))
if stamp and stamp in recent_wakes and now - recent_wakes[stamp] < 30:
    log_state("忽略重复唤醒事件(固件重发)", "listen")
    continue
```

实测固件会在一次唤醒后重发数次，30 秒窗口足够。

## 4. 上位机可下发的命令（0x05）

```python
mic.cmd_json({"type": "version"})
mic.cmd_json({"type": "manual_wakeup", "content": {"beam": 0}})
mic.cmd_json({"type": "wakeup_keywords",
              "content": {"keyword": "ni2 hao3 kuan1 kuan1", "threshold": "900"}})
mic.cmd_json({"type": "switch_mic", "content": {"mic": "m2n"}})
mic.cmd_json({"type": "get_original_audio", "content": {"audio": 0}})
```

| 命令 | 作用 |
|---|---|
| `version` | 查固件版本 |
| `manual_wakeup` | 手动唤醒 / 设定波束（0-5），**调试神器，不用喊** |
| `wakeup_keywords` | 更换唤醒词（拼音串 + 阈值） |
| `switch_mic` | 切换麦克风类型（仅 M2 系列） |
| `get_original_audio` | 原始音频流开关 |

### `cmd_json()` 为什么要"先应答后发送"

固件刚上电时会**连续发一堆握手帧**，此时发命令它会忽略。所以：

```
阶段1：一直回 0xFF 确认，直到 1 秒内没有新帧（突发结束）
阶段2：发命令，等回包；无回应则重发，最多 3 次
```

## 5. 端口自动识别

两级策略（`MicSerial.autodetect`）：

```python
1) detect_by_usb(prefer=("1a86", "55d4"))   # 按 USB 芯片 ID 确定性匹配
   └ 沿 sysfs 向上找 idVendor/idProduct —— 不依赖设备是否正在发握手帧
2) 失败则退化为"扫描候选端口 + 找握手帧"
   └ 遍历 /dev/wheeltec_mic* → /dev/ttyACM* → /dev/ttyUSB*
```

**为什么优先按 USB ID**：等握手帧要 1.5s 且要求在设备刚上电的窗口期内；
按 USB ID 查 sysfs 是瞬时的、确定性的。

**udev 别名**：文档建议的 `wheeltec_mic` 别名在本机**尚未创建**（`/dev/wheeltec_mic*` 不存在），
所以实际走的是 `/dev/ttyACMN` + USB ID 识别。想加别名可以写 udev 规则：

```
SUBSYSTEM=="tty", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="55d4", SYMLINK+="wheeltec_mic"
```

## 6. 常见硬件问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `未找到降噪板串口` | USB 没插好 / 驱动缺失 | `lsusb \| grep 1a86`、`dmesg \| tail` 看是否枚举成功 |
| 串口打开后线程静默死亡 | `termios.error` **不是** `OSError` 子类 | 已在 `MicSerial.open()` 内捕获转 `SerialTimeoutError` 并关 fd |
| 写串口报 `BlockingIOError [Errno 11]` | 非阻塞 fd 写满 | 已改为 `select` 等可写 + 处理 EAGAIN |
| 唤醒响应慢/不灵 | 唤醒阈值不合适 | `voice_interact_test.py --threshold 900`（越大越难） |
| 改了唤醒词不生效 | 需重新枚举 USB | 改完**拔插音箱** |
| 声源角度显示"未知" | 载荷是 bytes 且嵌套 | 已改为先 `json.loads` 再递归提取 |
