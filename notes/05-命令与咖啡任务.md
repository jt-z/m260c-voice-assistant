# 05 - 命令与咖啡任务

## 1. 命令词表

```python
# voice_command_demo.py
COMMANDS = [
    (("咖啡",), make_coffee),                        # 给我倒杯咖啡
    (("水果", "香蕉", "桃子", "桃", "蕉", "banana", "peach"), pick_fruit),  # 夹香蕉 / 夹桃子
    (("关闭", "关掉", "闭", "收起"), close_image),
    (("图片", "照片", "看图", "图像", "图"), open_newest_image),
]
```

### 匹配规则：**包含匹配 + 顺序即优先级**

```python
def dispatch(text):
    for keywords, action in COMMANDS:
        if any(k in text for k in keywords):     # 子串包含，不是相等
            action(text)
            return True
    return False
```

两个要点：

1. **用包含而不是相等** —— 识别结果通常带唤醒词（`你好宽宽打开图片`），
   包含匹配能直接命中，不需要先剥唤醒词。
2. **顺序就是优先级** —— 同一句话命中多个命令时，排前面的赢。
   所以 `("关闭", ...)` 必须排在 `("图片", ...)` 之前，
   否则「关闭图片」会先被"图片"截走，变成"打开图片"。

> **曾经的坑**：早期版本 `COMMANDS` 定义在动作函数**之前**，
> 引用 `make_coffee` 时抛 `NameError`。现在统一放在所有动作函数之后。

## 2. 图片功能

### 打开：`open_newest_image`

```python
IMAGE_DIRS = ["~/Desktop", "~/Pictures"]      # 桌面优先，无图回退到图片文件夹
IMAGE_EXT  = (".jpg", ".jpeg", ".png", ".bmp", ".webp", ".gif", ".tif", ".tiff", ".svg")
```

递归遍历两个目录，按 `os.path.getmtime` 排序取最新的一个，
用 `xdg-open` 打开（`start_new_session=True`，脱离本程序进程组）。

打开的路径记到 `_last_opened`，供"关闭图片"使用。

### 关闭：`close_image`

**只关自己打开的那一张**，实现方式是按**文件路径**匹配进程：

```python
for pid in os.listdir("/proc"):
    cmdline = open(f"/proc/{pid}/cmdline").read().decode()
    if _last_opened in cmdline:        # 该进程正在查看这张图
        pids.append(int(pid))
for pid in pids:
    os.kill(pid, signal.SIGTERM)
```

比"杀所有图片查看器"安全得多。如果窗口已被手动关闭，会提示并清空 `_last_opened`。

## 3. 机械臂任务（咖啡回放 / 水果抓取）

### 3.1 需求演变（重要背景）

需求改过两轮，最终形态是**「启动即撒手」**：

| 阶段 | 形态 | 为什么改 |
|---|---|---|
| 初版 | 后台 PIPE 跑脚本 + 跟踪完成/超时/语音收尾 | 用户要求"能语音收尾或按键退出" |
| 中间版 | 加语音「做好了」注入 n 键、超时 120s 中断、做咖啡期间屏蔽其它命令 | 逻辑复杂，user 觉得多余 |
| **最终版** | **新开 gnome-terminal 窗口跑脚本，本程序完全不管** | 用户明确要求「启动之后就不管了，先这样实现」 |

**根本原因**：早期推理脚本**无法从画面判断咖啡是否做好了**，ACT 会一直推理下去，何时结束只有
现场的人最清楚。所以最合适的是把控制权交回给人，用脚本自带的交互，而不是让语音程序去猜
（当前默认脚本已换成数据回放 `replay.sh`，同样是"跑起来就交给窗口里的人管"）。

### 3.2 现在的实现

```python
COFFEE_SCRIPT = "/home/kf/LX/pai0/tool/b601_single/replay.sh"
COFFEE_TERM_TITLE = "咖啡任务"
FRUIT_SCRIPT = "/home/kf/LX/pai0/tool/101_single/fruit_inference_101.sh"
# 所有机械臂任务共用一个槽位 _arm：同一时刻只允许一个在跑（两进程抢同一台机械臂危险）
_arm = {"proc": None, "title": ""}      # 当前终端任务进程（存活 = 窗口还开着），防重复启动
```

**流程**：

```
说「给我倒杯咖啡」/「夹香蕉」/「夹桃子」
   ↓
make_coffee() / pick_fruit(text)        # 水果任务先从话里解析出 banana / peach
   ├─ 已有机械臂任务窗口还开着？ → 播「已有机械臂任务在运行…」并忽略本次
   └─ 否则起后台线程 _arm_launch(...)
         ↓
      _arm_launch()
        ├─ 检查脚本存在 / gnome-terminal 存在 / X 环境可用（ensure_x_display）
        ├─ 播报开始语（异步，不阻塞）
        └─ Popen: gnome-terminal --title=<标题> --wait -- bash -c "<命令>"
             ↓
           终端里执行：bash <脚本> [水果参数]; rc=$?; 报告退出码; read 等回车关窗
```

生成的终端命令（[`_arm_term_cmd`](../voice_command_demo.py)）：

```bash
# 咖啡（无参数）
bash /home/kf/LX/pai0/tool/b601_single/replay.sh; rc=$?; \
printf '%s' "$rc" > <项目目录>/.arm_last_result; echo; \
echo "[咖啡] 脚本已结束，退出码 $rc"; read -r -p "[咖啡] 按回车关闭本窗口 " _

# 水果（第一个参数选水果：banana / peach；前面加 DURATION=120 作兜底超时）
DURATION=120 bash /home/kf/LX/pai0/tool/101_single/fruit_inference_101.sh banana; rc=$?; \
printf '%s' "$rc" > <项目目录>/.arm_last_result; echo; \
echo "[水果] 脚本已结束，退出码 $rc"; read -r -p "[水果] 按回车关闭本窗口 " _
```

**为什么用 `--wait`**：让 gnome-terminal 客户端进程的生命周期 = 窗口生命周期，
这样 `_arm["proc"]` 天然就是一个可靠的"窗口是否还开着"的判据，用于防重复启动。

**为什么 `read` 等回车**：脚本跑完窗口不能立刻消失，否则用户看不到日志、翻不回历史。

**结果回传（半闭环）**：包装脚本在脚本结束处把退出码写进 `.arm_last_result`，
主程序一边等窗口、一边每 0.5s 探一次该文件，**一出现就播报**（不必等用户按回车关窗）：

| 结果文件 | 播报 |
|---|---|
| `0` / `130`（Ctrl+C） | 「{任务}已完成」 |
| 其它整数 | 「{任务}异常结束，请查看窗口」 |
| 文件不存在（窗口被直接关掉） | 「{任务}窗口已关闭」 |

> 注意这是**退出码级**的"完成/异常"，**不是"是否真的夹到"**——真正的成功检测需要额外视觉/传感器判据，见第 6 节。

### 3.3 窗口里的操作（和手动跑脚本完全一致）

`replay.sh` 会把指定 episode 的 action 序列按数据集 fps 逐帧下发给从臂，回放结束/断开时 `safe_zero` 回零位。

| 操作 | 效果 |
|---|---|
| 按 **ENTER** | 确认安全提示后开始回放 |
| `Ctrl+C` | 中断（走脚本的异常处理路径，机械臂安全回零位） |
| 直接关掉终端窗口 | 结束本次任务（脚本进程随窗口一起结束） |

> ⚠️ **安全**：回放下发的是**绝对目标角**（episode 首帧坐标系）。
> 若当前从臂位姿与首帧差得多，会**猛地甩到首帧位置**。
> 开始前请把从臂摆到接近首帧姿态、留出运动空间，并把手放在急停/电源附近。
> 脚本参数详见第 4 节。

### 3.4 本程序做的事 / 不再做的事

**不做**：
- ❌ 不判断"咖啡做好了 / 水果夹到了"（脚本没有这个能力，见第 6 节）
- ❌ 不注入按键、不响应「做好了」/「停止」
- ❌ 不主动中断脚本（咖啡由脚本自己结束；水果用脚本自带的 `DURATION` 兜底超时，见 3.6）

**做两件事**：
1. **防重复启动**：两个机械臂进程同时抢同一台机械臂是危险的，只要任一任务窗口还开着（咖啡或水果），再发起都会被拦下；
2. **完成后播报**：脚本结束时按退出码播报"完成 / 异常"（见 3.2 结果回传）。

### 3.5 手动提前结束

因为本程序撒手了，要停只能：

```bash
# 方式 1：在任务窗口里 Ctrl+C（推荐，机械臂安全回零位）

# 方式 2：直接关掉那个终端窗口（gnome-terminal 返回码会是 137）
```

### 3.6 水果抓取（夹香蕉 / 夹桃子）

复用 3.2 的同一套机制，只是脚本换成一个按水果传参的入口：

```python
FRUIT_SCRIPT = "/home/kf/LX/pai0/tool/101_single/fruit_inference_101.sh"

# 话里出现哪个词就选哪种水果（也接受英文别名）
FRUIT_WORDS = (
    ("banana", ("香蕉", "蕉", "banana")),
    ("peach",  ("桃子", "桃", "peach")),
)
```

`pick_fruit(text)` 的规则：

| 你说 | 行为 |
|---|---|
| 夹香蕉 / 抓蕉 / pick banana | `fruit_inference_101.sh banana`（036000banana，数据集 so101_banana_101ep） |
| 夹桃子 / 拿桃 | `fruit_inference_101.sh peach`（042000peach，数据集 so101_peach_100ep） |
| 夹水果（没说哪种） | 不启动任务，播「请问要夹香蕉还是桃子」 |
| 窗口里 | 先按 ENTER 开始推理，运行中 Ctrl+C 中断 |

**兜底超时**：`fruit_inference_101.sh` 本身不带时长，底层 `act_inference_101.sh` 默认 `DURATION=0`
（**一直推理到 Ctrl+C**）。主程序启动水果任务时用环境变量给它一个上限：

```python
FRUIT_DURATION = 120                       # 秒；0 = 不限
env = {"DURATION": str(FRUIT_DURATION)} if FRUIT_DURATION else None
# 生成的命令: DURATION=120 bash fruit_inference_101.sh banana
```

用 `--fruit-duration 0` 可关掉兜底（恢复"跑到 Ctrl+C"）。

> `fruit_inference_101.sh` 只把「水果 → 权重路径 + 任务描述」这层定死，
> 其余（从臂串口、相机、校准、检查）全部复用 `act_inference_101.sh`；想临时换权重用环境变量
> `MODEL_PATH` / `TASK_DESCRIPTION` 覆盖。脚本路径可用 `--fruit-script` 替换。

## 4. 咖啡脚本本身（[`replay.sh`](../../../LX/pai0/tool/b601_single/replay.sh)）

**用途**：把**已录 episode 的 action 序列原样下发**给从臂（`lerobot-replay`），
用于验证某次采集轨迹在真机上是否物理可复现。**不推理、不录制**。

关键参数：

| 变量 | 值 | 说明 |
|---|---|---|
| `DATASET_ROOT` | `~/LX/pai0/b601_data/b601_20260915_141534` | 回放数据集（本地 root，不上传/不下载） |
| `EPISODE` | `0` | 回放第几集 |
| `FPS` | `30` | 与采集一致（实际以数据集 `meta` 里的 fps 为准） |
| `B601_FOLLOWER_PORT` | `can0` | SocketCAN（PEAK PCAN-USB，1Mbps 经典 CAN） |
| `B601_JOINT_DIRECTIONS` | 全 `-1.0` | **必须与采集时一致**，否则下发方向反 |
| `USE_RERUN` | `1` | 用 `tool/replay_rerun.py` 把 `observation.state` + 三路相机画面送 rerun 显示 |
| `REPLAY_RERUN` | `tool/replay_rerun.py` | 原生 `lerobot-replay` 没有显示选项，靠它补上可视化 |

启动前会逐项检查：数据集路径与 `meta/info.json`、`can0` 是否 UP（不 UP 会自动配 1Mbps 并拉起）、
从臂校准文件 `~/.cache/huggingface/lerobot/calibration/robots/seeed_b601_rs_follower/follower.json`、
以及 rerun 是否安装；并打印 episode 首帧 `state`/`action` 供对照当前位姿。

回放结束或断开时执行 `safe_zero`，机械臂安全回零位。

> 原默认脚本是 ACT 推理脚本 `run_inference_b601_make_coffee_ACT_50k.sh`（模型推理 + 录制，需 ACT 权重），
> 现已换成数据回放脚本；如需推理，用 `--coffee-script` 指回推理脚本即可。

## 6. 局限：机械臂任务目前只是"半闭环"

主程序只拿到**退出码级**结果（完成 / 异常），**拿不到"是否真的夹到了"**，也没有"夹到就停"。
这在水果任务（base 无限推理）上尤其明显：

| 缺口 | 现状 | 后果 |
|---|---|---|
| 成功检测 | 无（无视觉/夹爪判据） | 不知道有没有夹到 |
| 自动终止 | 咖啡靠脚本自然结束；水果靠 `DURATION` 兜底超时 | 不能"夹到即停"，只能等超时或人工 Ctrl+C |
| 结果回传 | 只有退出码（`.arm_last_result`） | 无法区分"夹到了"和"跑了 120 秒没夹到" |

**要做真正的闭环，需要补**：

1. **成功检测**：用第三视角相机（`observation.images.front`）判断"目标物消失 / 进入盘子"，或读夹爪负载/位置；
2. **终止条件**：检测到成功 → 停止 rollout 并 `safe_zero`；
3. **结构化回传**：脚本结束时输出约定结果（如 `[RESULT] banana ok/fail`），替代/扩展退出码；
4. **主程序侧**：解析该结果 → 播报「夹好了 / 没夹到」+ 更新 HUD。

> 其中 1、2 需要机械臂侧新增检测逻辑，不由本项目凭空实现，**接口需先对齐**。
