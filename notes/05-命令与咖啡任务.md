# 05 - 命令与咖啡任务

## 1. 命令词表

```python
# voice_command_demo.py
COMMANDS = [
    (("咖啡",), make_coffee),                        # 给我倒杯咖啡
    (("关闭", "关掉", "闭", "收起"), close_image),
    (("图片", "照片", "看图", "图像", "图"), open_newest_image),
]
```

### 匹配规则：**包含匹配 + 顺序即优先级**

```python
def dispatch(text):
    for keywords, action in COMMANDS:
        if any(k in text for k in keywords):     # 子串包含，不是相等
            action(text)
            return True
    return False
```

两个要点：

1. **用包含而不是相等** —— 识别结果通常带唤醒词（`你好宽宽打开图片`），
   包含匹配能直接命中，不需要先剥唤醒词。
2. **顺序就是优先级** —— 同一句话命中多个命令时，排前面的赢。
   所以 `("关闭", ...)` 必须排在 `("图片", ...)` 之前，
   否则「关闭图片」会先被"图片"截走，变成"打开图片"。

> **曾经的坑**：早期版本 `COMMANDS` 定义在动作函数**之前**，
> 引用 `make_coffee` 时抛 `NameError`。现在统一放在所有动作函数之后。

## 2. 图片功能

### 打开：`open_newest_image`

```python
IMAGE_DIRS = ["~/Desktop", "~/Pictures"]      # 桌面优先，无图回退到图片文件夹
IMAGE_EXT  = (".jpg", ".jpeg", ".png", ".bmp", ".webp", ".gif", ".tif", ".tiff", ".svg")
```

递归遍历两个目录，按 `os.path.getmtime` 排序取最新的一个，
用 `xdg-open` 打开（`start_new_session=True`，脱离本程序进程组）。

打开的路径记到 `_last_opened`，供"关闭图片"使用。

### 关闭：`close_image`

**只关自己打开的那一张**，实现方式是按**文件路径**匹配进程：

```python
for pid in os.listdir("/proc"):
    cmdline = open(f"/proc/{pid}/cmdline").read().decode()
    if _last_opened in cmdline:        # 该进程正在查看这张图
        pids.append(int(pid))
for pid in pids:
    os.kill(pid, signal.SIGTERM)
```

比"杀所有图片查看器"安全得多。如果窗口已被手动关闭，会提示并清空 `_last_opened`。

## 3. 咖啡任务

### 3.1 需求演变（重要背景）

需求改过两轮，最终形态是**「启动即撒手」**：

| 阶段 | 形态 | 为什么改 |
|---|---|---|
| 初版 | 后台 PIPE 跑脚本 + 跟踪完成/超时/语音收尾 | 用户要求"能语音收尾或按键退出" |
| 中间版 | 加语音「做好了」注入 n 键、超时 120s 中断、做咖啡期间屏蔽其它命令 | 逻辑复杂，user 觉得多余 |
| **最终版** | **新开 gnome-terminal 窗口跑脚本，本程序完全不管** | 用户明确要求「启动之后就不管了，先这样实现」 |

**根本原因**：推理脚本**无法从画面判断咖啡是否做好了**，ACT 会一直推理下去。
只有人在旁边看着才能决定何时结束 —— 所以最合适的是把控制权交回给人，
用脚本自带的按键交互，而不是让语音程序去猜。

### 3.2 现在的实现

```python
COFFEE_SCRIPT = "/home/kf/LX/pai0/run_inference_b601_make_coffee_ACT_50k.sh"
COFFEE_TERM_TITLE = "咖啡任务(ACT 推理)"
_coffee = {"proc": None}        # gnome-terminal 进程（存活 = 窗口还开着），防重复启动
```

**流程**：

```
说「给我倒杯咖啡」
   ↓
make_coffee()
   ├─ 已有咖啡窗口还开着？ → 播「正在制作中，请稍候」并忽略本次指令
   └─ 否则起后台线程 _coffee_launch()
         ↓
      _coffee_launch()
        ├─ 检查脚本存在 / gnome-terminal 存在 / X 环境可用（ensure_x_display）
        ├─ 播报「好的，开始为你制作咖啡」（异步，不阻塞）
        └─ Popen: gnome-terminal --title=<标题> --wait -- bash -c "<命令>"
             ↓
           终端里执行：bash <脚本>; rc=$?; 报告退出码; read 等回车关窗
```

生成的终端命令（[`_coffee_term_cmd`](../voice_command_demo.py)）：

```bash
bash /home/kf/LX/pai0/run_inference_b601_make_coffee_ACT_50k.sh; rc=$?; echo; \
echo "[咖啡] 脚本已结束，退出码 $rc"; read -r -p "[咖啡] 按回车关闭本窗口 " _
```

**为什么用 `--wait`**：让 gnome-terminal 客户端进程的生命周期 = 窗口生命周期，
这样 `_coffee["proc"]` 天然就是一个可靠的"窗口是否还开着"的判据，用于防重复启动。

**为什么 `read` 等回车**：脚本跑完窗口不能立刻消失，否则用户看不到日志、翻不回历史。

### 3.3 窗口里的操作（和手动跑脚本完全一致）

| 操作 | 效果 |
|---|---|
| 按**回车** | 跳过脚本的"确认零位"提示，开始推理 |
| 按 `n`（或 `→`） | **提前结束当前 episode 并正常收尾保存** |
| 按 `r`（或 `←`） | 重录上一集 |
| 按 `q`（或 `ESC`） | 停止整个录制 |
| `Ctrl+C` | 中断（走脚本的异常处理路径，机械臂安全回零位） |

> ⚠️ **注意**：lerobot 只有 `n` / `r` / `q` 三个键，**没有 `d` 键**。
> 定义见 `/home/kf/LX/pai0/lerobot/src/lerobot/utils/keyboard_input.py`。
> 另外按键是 **pynput 全局监听**，所以运行期间在**别的窗口**敲到这几个字母也会被当成控制键。

### 3.4 本程序不再做的事

- ❌ 不判断"咖啡做好了"（脚本没有这个能力）
- ❌ 不设超时中断
- ❌ 不注入按键、不响应「做好了」/「停止」
- ❌ 不在咖啡期间屏蔽其它语音命令

**保留的唯一干预**：防重复启动。两个 ACT 进程同时抢机械臂是危险的，
所以只要咖啡窗口还开着，再说「给我倒杯咖啡」会被拦下。

### 3.5 手动提前结束

因为本程序撒手了，要停只能：

```bash
# 方式 1：在咖啡窗口里按键（推荐）
n     # 正常收尾
q     # 停止录制
Ctrl+C

# 方式 2：直接关掉那个终端窗口（gnome-terminal 返回码会是 137）
```

## 4. 咖啡脚本本身（[`run_inference_b601_make_coffee_ACT_50k.sh`](../../../LX/pai0/run_inference_b601_make_coffee_ACT_50k.sh)）

关键参数：

| 变量 | 值 | 说明 |
|---|---|---|
| `MODEL_PATH` | `~/LX/pai0/50kact_b601/pretrained_model` | ACT 50k 权重 |
| `B601_FOLLOWER_PORT` | `can0` | SocketCAN，PEAK PCAN-USB，1Mbps |
| `B601_JOINT_DIRECTIONS` | 全 `-1.0` | **必须与采集时一致**，否则动作方向反 |
| `MAX_RELATIVE_TARGET` | 100 | 每 tick 相对动作上限（度/步），安全帽 |
| `EPISODE_TIME` | 600 | 单集推理时长上限（秒） |
| `FPS` | 30 | 必须与训练数据一致 |
| `num_episodes` | 1 | 只录一集 |
| `PUSH_TO_HUB` | false | 不传 HuggingFace |
| `--play_sounds` | **false** | 关掉 lerobot 的英文语音播报（见下） |

启动前会逐项检查：模型文件、`can0` 是否 UP、3 路相机、从臂校准文件。

### 为什么加了 `--play_sounds=false`

lerobot 默认 `play_sounds=True`，实现是调 `spd-say` 念英文事件：

```python
# lerobot/utils/utils.py
def log_say(text, play_sounds=True, blocking=False):
    logging.info(text)
    if play_sounds:
        say(text, blocking)      # Linux: subprocess.Popen(["spd-say", text])
```

会念 `Recording episode 0`、`Reset the environment`、`Stop recording`、`Exiting` 等。

**但注意**：那个"十几秒的怪音"其实**不是它**，而是我们自己 TTS 的兜底分支
（edge-tts 失败退到 `spd-say -l zh` 用 espeak-ng 读中文）。详见 03 篇第 4.1 节。
`--play_sounds=false` 是顺带一起关掉的。
