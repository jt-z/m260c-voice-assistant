# 05 - 命令与咖啡任务

## 1. 命令词表

```python
# voice_command_demo.py
COMMANDS = [
    (("咖啡",), make_coffee),                        # 给我倒杯咖啡
    (("关闭", "关掉", "闭", "收起"), close_image),
    (("图片", "照片", "看图", "图像", "图"), open_newest_image),
]
```

### 匹配规则：**包含匹配 + 顺序即优先级**

```python
def dispatch(text):
    for keywords, action in COMMANDS:
        if any(k in text for k in keywords):     # 子串包含，不是相等
            action(text)
            return True
    return False
```

两个要点：

1. **用包含而不是相等** —— 识别结果通常带唤醒词（`你好宽宽打开图片`），
   包含匹配能直接命中，不需要先剥唤醒词。
2. **顺序就是优先级** —— 同一句话命中多个命令时，排前面的赢。
   所以 `("关闭", ...)` 必须排在 `("图片", ...)` 之前，
   否则「关闭图片」会先被"图片"截走，变成"打开图片"。

> **曾经的坑**：早期版本 `COMMANDS` 定义在动作函数**之前**，
> 引用 `make_coffee` 时抛 `NameError`。现在统一放在所有动作函数之后。

## 2. 图片功能

### 打开：`open_newest_image`

```python
IMAGE_DIRS = ["~/Desktop", "~/Pictures"]      # 桌面优先，无图回退到图片文件夹
IMAGE_EXT  = (".jpg", ".jpeg", ".png", ".bmp", ".webp", ".gif", ".tif", ".tiff", ".svg")
```

递归遍历两个目录，按 `os.path.getmtime` 排序取最新的一个，
用 `xdg-open` 打开（`start_new_session=True`，脱离本程序进程组）。

打开的路径记到 `_last_opened`，供"关闭图片"使用。

### 关闭：`close_image`

**只关自己打开的那一张**，实现方式是按**文件路径**匹配进程：

```python
for pid in os.listdir("/proc"):
    cmdline = open(f"/proc/{pid}/cmdline").read().decode()
    if _last_opened in cmdline:        # 该进程正在查看这张图
        pids.append(int(pid))
for pid in pids:
    os.kill(pid, signal.SIGTERM)
```

比"杀所有图片查看器"安全得多。如果窗口已被手动关闭，会提示并清空 `_last_opened`。

## 3. 咖啡任务

### 3.1 需求演变（重要背景）

需求改过两轮，最终形态是**「启动即撒手」**：

| 阶段 | 形态 | 为什么改 |
|---|---|---|
| 初版 | 后台 PIPE 跑脚本 + 跟踪完成/超时/语音收尾 | 用户要求"能语音收尾或按键退出" |
| 中间版 | 加语音「做好了」注入 n 键、超时 120s 中断、做咖啡期间屏蔽其它命令 | 逻辑复杂，user 觉得多余 |
| **最终版** | **新开 gnome-terminal 窗口跑脚本，本程序完全不管** | 用户明确要求「启动之后就不管了，先这样实现」 |

**根本原因**：早期推理脚本**无法从画面判断咖啡是否做好了**，ACT 会一直推理下去，何时结束只有
现场的人最清楚。所以最合适的是把控制权交回给人，用脚本自带的交互，而不是让语音程序去猜
（当前默认脚本已换成数据回放 `replay.sh`，同样是"跑起来就交给窗口里的人管"）。

### 3.2 现在的实现

```python
COFFEE_SCRIPT = "/home/kf/LX/pai0/tool/b601_single/replay.sh"
COFFEE_TERM_TITLE = "咖啡任务(数据回放)"
_coffee = {"proc": None}        # gnome-terminal 进程（存活 = 窗口还开着），防重复启动
```

**流程**：

```
说「给我倒杯咖啡」
   ↓
make_coffee()
   ├─ 已有咖啡窗口还开着？ → 播「正在制作中，请稍候」并忽略本次指令
   └─ 否则起后台线程 _coffee_launch()
         ↓
      _coffee_launch()
        ├─ 检查脚本存在 / gnome-terminal 存在 / X 环境可用（ensure_x_display）
        ├─ 播报「好的，开始为你制作咖啡」（异步，不阻塞）
        └─ Popen: gnome-terminal --title=<标题> --wait -- bash -c "<命令>"
             ↓
           终端里执行：bash <脚本>; rc=$?; 报告退出码; read 等回车关窗
```

生成的终端命令（[`_coffee_term_cmd`](../voice_command_demo.py)）：

```bash
bash /home/kf/LX/pai0/tool/b601_single/replay.sh; rc=$?; echo; \
echo "[咖啡] 脚本已结束，退出码 $rc"; read -r -p "[咖啡] 按回车关闭本窗口 " _
```

**为什么用 `--wait`**：让 gnome-terminal 客户端进程的生命周期 = 窗口生命周期，
这样 `_coffee["proc"]` 天然就是一个可靠的"窗口是否还开着"的判据，用于防重复启动。

**为什么 `read` 等回车**：脚本跑完窗口不能立刻消失，否则用户看不到日志、翻不回历史。

### 3.3 窗口里的操作（和手动跑脚本完全一致）

`replay.sh` 会把指定 episode 的 action 序列按数据集 fps 逐帧下发给从臂，回放结束/断开时 `safe_zero` 回零位。

| 操作 | 效果 |
|---|---|
| 按 **ENTER** | 确认安全提示后开始回放 |
| `Ctrl+C` | 中断（走脚本的异常处理路径，机械臂安全回零位） |
| 直接关掉终端窗口 | 结束本次任务（脚本进程随窗口一起结束） |

> ⚠️ **安全**：回放下发的是**绝对目标角**（episode 首帧坐标系）。
> 若当前从臂位姿与首帧差得多，会**猛地甩到首帧位置**。
> 开始前请把从臂摆到接近首帧姿态、留出运动空间，并把手放在急停/电源附近。
> 脚本参数详见第 4 节。

### 3.4 本程序不再做的事

- ❌ 不判断"咖啡做好了"（脚本没有这个能力）
- ❌ 不设超时中断
- ❌ 不注入按键、不响应「做好了」/「停止」
- ❌ 不在咖啡期间屏蔽其它语音命令

**保留的唯一干预**：防重复启动。两个回放进程同时抢机械臂是危险的，
所以只要咖啡窗口还开着，再说「给我倒杯咖啡」会被拦下。

### 3.5 手动提前结束

因为本程序撒手了，要停只能：

```bash
# 方式 1：在咖啡窗口里 Ctrl+C（推荐，机械臂安全回零位）

# 方式 2：直接关掉那个终端窗口（gnome-terminal 返回码会是 137）
```

## 4. 咖啡脚本本身（[`replay.sh`](../../../LX/pai0/tool/b601_single/replay.sh)）

**用途**：把**已录 episode 的 action 序列原样下发**给从臂（`lerobot-replay`），
用于验证某次采集轨迹在真机上是否物理可复现。**不推理、不录制**。

关键参数：

| 变量 | 值 | 说明 |
|---|---|---|
| `DATASET_ROOT` | `~/LX/pai0/b601_data/b601_20260915_141534` | 回放数据集（本地 root，不上传/不下载） |
| `EPISODE` | `0` | 回放第几集 |
| `FPS` | `30` | 与采集一致（实际以数据集 `meta` 里的 fps 为准） |
| `B601_FOLLOWER_PORT` | `can0` | SocketCAN（PEAK PCAN-USB，1Mbps 经典 CAN） |
| `B601_JOINT_DIRECTIONS` | 全 `-1.0` | **必须与采集时一致**，否则下发方向反 |
| `USE_RERUN` | `1` | 用 `tool/replay_rerun.py` 把 `observation.state` + 三路相机画面送 rerun 显示 |
| `REPLAY_RERUN` | `tool/replay_rerun.py` | 原生 `lerobot-replay` 没有显示选项，靠它补上可视化 |

启动前会逐项检查：数据集路径与 `meta/info.json`、`can0` 是否 UP（不 UP 会自动配 1Mbps 并拉起）、
从臂校准文件 `~/.cache/huggingface/lerobot/calibration/robots/seeed_b601_rs_follower/follower.json`、
以及 rerun 是否安装；并打印 episode 首帧 `state`/`action` 供对照当前位姿。

回放结束或断开时执行 `safe_zero`，机械臂安全回零位。

> 原默认脚本是 ACT 推理脚本 `run_inference_b601_make_coffee_ACT_50k.sh`（模型推理 + 录制，需 ACT 权重），
> 现已换成数据回放脚本；如需推理，用 `--coffee-script` 指回推理脚本即可。
