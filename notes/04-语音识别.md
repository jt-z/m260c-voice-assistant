# 04 - 语音识别

## 1. 两个引擎的分工

| 引擎 | 角色 | 特点 |
|---|---|---|
| **Vosk**（`vosk-model-small-cn-0.22`） | 回退方案（`--asr vosk`） | 轻量、真流式、逐字出结果；但中文精度差、爱吐重复字 |
| **SenseVoice**（`iic/SenseVoiceSmall`） | **默认** | 精度好、句子完整；但**非流式**，需要"滚动重解码"来模拟实时 |

默认走 SenseVoice（`--asr sv`）。切换：`--asr vosk`。

### 为什么换掉 Vosk

用 [`bench_asr.py`](../bench_asr.py) 在同一批录音上做代理指标对比：

| 指标 | 含义 |
|---|---|
| 命中命令词比例 | 文本里是否出现 打开/关闭/看/图片/照片 |
| 命令完整率 | 是否同时含 (打开\|关闭\|关掉\|看) 且 (图片\|照片) |
| 无异常重复字 | 是否出现 3 个以上连续相同字符（如 `关关关`） |
| 空结果 | 完全没识别出内容 |
| 平均耗时 | 单条解码时间 |

历史实测结论：**SenseVoice 在"无重复字"和"空结果"两项上明显优于 Vosk**
（Vosk 经常吐 `开开开图片` 这种，或者干脆空结果），代价是耗时略长（但仍在 0.1~0.25s 级别）。

另外 SenseVoice 会**完整还原整句话**（包括唤醒词"你好宽宽"），
不会像 Vosk 那样因语法限制把不认识的部分丢掉 —— 这对误触发判断反而更安全。

## 2. Vosk 路径（`--asr vosk`）

```python
# voice_command_demo.py
MODEL_DIR = "models/vosk-model-small-cn-0.22"
VOSK_GRAMMAR = ('["打 开 图 片", "打 开 照 片", "看 一 下 图 片", '
                '"关 闭 图 片", "关 掉 图 片", "[unk]"]')

def load_recognizer():
    model = Model(MODEL_DIR)
    return KaldiRecognizer(model, WAV_RATE, VOSK_GRAMMAR)   # 16kHz + 语法限制
```

**语法限制的写法**：Vosk 中文模型词表是按**字**的，所以语法里的词要用空格分隔成单字
（`"打 开 图 片"` 而不是 `"打开图片"`）。

**流式用法**：每个音频块喂 `AcceptWaveform()`，返回 True 说明出一句完整结果
（`Result()`），否则取 `PartialResult()` 做实时显示。

> ⚠️ **注意**：`VOSK_GRAMMAR` 目前**只包含图片相关的句子**，没有咖啡命令。
> 如果用 `--asr vosk` 说「给我倒杯咖啡」，很可能被限制成 `[unk]`。
> 需要 Vosk 模式也支持咖啡的话，要往语法里补 `"咖 啡"` 等条目。

## 3. SenseVoice 路径（默认）

### 3.1 封装（[`asr_sensevoice.py`](../asr_sensevoice.py)）

```python
class SenseVoice:
    def __init__(self, model="iic/SenseVoiceSmall", device="cpu", hub="ms"):
        from funasr import AutoModel
        _quiet_logs()                          # 压掉 funasr/modelscope 的 INFO 噪音
        self.model = AutoModel(model=model, device=device, disable_update=True,
                               disable_pbar=True, hub=hub, log_level="ERROR")

    def decode(self, wav_path) -> str:         # 识别 WAV 文件
    def decode_pcm(self, pcm: bytes) -> str:   # 识别内存 PCM（滚动重解码用，不落盘）
```

| 项 | 值 |
|---|---|
| 模型 | `iic/SenseVoiceSmall`（约 936MB，缓存在 `~/.cache/modelscope`） |
| 加载耗时 | 约 5~6s（**全程只加载一次**） |
| 单次识别 | 0.1~0.25s（3~4s 音频，RTF ≈ 0.03，CPU） |
| 输出清理 | 去掉 `<\|zh\|>` `<\|NEUTRAL\|>` 等标记 + 去掉全部标点空白 |

```python
_TAG  = re.compile(r"<\|[^|]*\|>")
_PUNC = re.compile(r"[，。！？、,.!?\s]")
```

`decode_pcm()` 内部把 S16LE 字节流转成 float32 数组直接喂模型，**避免写临时文件**
（滚动重解码每 0.5s 调一次，落盘很浪费）。少于 0.1s（3200 字节）的音频直接返回空。

### 3.2 滚动重解码（把非流式模型用成"准实时"）

SenseVoice 不能像 Vosk 那样喂一块出一块。做法是**每新增约 0.5s 音频，
就把已录到的整段重新解码一次**：

```python
def _live_loop():
    decoded = 0
    while not stop_live.is_set():
        data = bytes(pcm)                                  # 当前已录到的全部 PCM
        if len(data) - decoded >= int(0.5 * 32000):        # 距上次解码多了 ≥0.5s
            decoded = len(data)
            t = _sv.decode_pcm(data)                       # 整段重解
            if t:
                push_live(t)                               # 推到终端(原地刷新)和 HUD
        stop_live.wait(0.1)
```

- **代价**：算力有重复消耗（后一段包含前一段），但 SenseVoice 很快，完全扛得住
- **收益**：用户说话过程中就能看到文本逐步变长，体验接近流式
- **收尾**：录音结束后停掉该线程，用**完整音频定稿**一次，结果为准

```python
sv_text = _sv.decode_pcm(bytes(pcm))     # 定稿：用完整音频再解一次
log(f"[识别] SenseVoice 定稿({耗时}ms): {sv_text}")
```

### 3.3 参数

```python
self.model.generate(input=..., cache={}, language="zh", use_itn=True)
```

- `language="zh"`：指定中文，避免自动语种识别的抖动
- `use_itn=True`：逆文本正则化，把"二零二六"变成"2026"（念出来更自然）

## 4. 识别文本的消费方

识别结果 `text` 会被送到两个地方，顺序固定（**命令优先**）：

```python
if text and dispatch(text):                  # ① 命令词包含匹配
    log_state("已执行命令，回到监听中", "done")
elif text and args.llm and ask_llm_and_speak(text):   # ② 大模型问答
    log_state("已播报大模型回复，回到监听中", "listen")
else:                                        # ③ 兜底语
    tts_speak("暂时还处理不了")
```

**识别结果通常带唤醒词**（"你好宽宽打开图片"），所以 `dispatch` 用**包含匹配**而非相等匹配，
这也是为什么不需要在送进 dispatch 前剥掉唤醒词。详见 05 篇。
